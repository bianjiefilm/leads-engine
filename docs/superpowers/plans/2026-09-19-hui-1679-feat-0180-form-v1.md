# 计划:HUI-1679【FEAT-0180】落地页与表单搭建·首版固定表单(版本化留资表单域)

- 日期:2026-09-19
- 票:HUI-1679 / FEAT-0180;分支 `hui-1679-feat-0180-form-v1`(本地,不 push)
- 基线:main = 86819bb(L0 + 商机域 + 客户档案 contact_consents + IntakeLeadInTx 去重接缝)
- brainstorm 指挥者已代答(拍板见票,本计划直接落为工程事实)
- 首版收敛:**先固定表单,不造搭建平台**;可视化自由拖拽搭建器延后,不作为线索闭环门槛。
  表单领域配置与语义归获客;碰一碰(T1/HUI-1747)只复用本票导出的固定渲染/校验契约,
  不建第二套通用表单系统;本票不改 touch-engine。

## 目标(本票只做)

所属商家的**固定字段留资表单 + 版本化 schema + 公共提交端点**:
明确必要字段/接收商家/用途/告知版本/单独营销许可及撤销方式;服务端字段校验、限流、
幂等、防重复提交;submission 原子写 contact + lead + consent;owner 管理面 CRUD 与
schema 契约导出;web 公共落地页(固定字段渲染)。

**不做**:自由字段/拖拽搭建器、可视化平台、接收渠道 inbox(HUI-1680)、营销触达(1689)、
touch-engine 改动(1747 后续对接)、contacts 的 wechat 扩列(见 deferred)。

## 硬边界(验收红线)

1. **无自由字段**:payload 键必须 ⊆ 表单 fields 白名单(固定枚举 name/phone/wechat)
   ∪ 控制字段 {marketing_allowed, source, source_ref};未知键一律 400。
2. **联系方式零 URL / 零全局 Context**:接收租户恒等于表单归属租户;
   `X-Tenant-ID` 头与 body 内任何租户字段对公共端点结构性无效(白名单外 → 400);
   日志只记手机号指纹前缀(redact 纪律,redact.Person/shortFPR 覆盖)。
3. **没有同意不进营销池**:`marketing_allowed` 独立勾选、服务端缺省 false;
   false 时 consent 行照写(marketing_allowed=0,仅建档,不进任何营销触达范围;
   触达语义归 HUI-1689)。撤销 = 复用 1691 撤销 API,撤销持久、重放不恢复。
4. **表单决定接收租户**:公共端点无会话,仅 BFF internal token;来源参数
   (source/source_ref)只是留痕,绝不能改变数据归属。
5. **版本不可变**:发布后表单配置不可改;改配置 = 同 form_key 新版本行(version 递增)。
6. **幂等与防重复**:
   - 同 (tenant, form, source, source_ref) 重试 → 返回原 submission(200 duplicate),零写入;
   - 同 contact+form 短窗内再次提交(不同 source_ref)→ 幂等提示,不新建
     (真实咨询次数语义归 1683 intake;短窗外的再次咨询走 IntakeLeadInTx 三分类,
     repeat_consult 新 lead 关联既有 contact,咨询次数不丢)。
7. **限流**:每 (IP, 表单) 30 次/分钟,进程内;第 31 次 → 429。
8. **权限**:管理面 ActionManageForms = owner 专属(新增 authz 动作,additive);
   sales/agent 一律 403。schema 导出属管理面(owner)。

## 数据模型(迁移 0006,全部 additive)

- `forms`(每行 = 一个版本):
  `id TEXT PK(frm_), tenant_id→tenants, store_id TEXT NOT NULL DEFAULT ''(可空门店归属,
  ''=租户级;无 stores 表故不设 FK), form_key TEXT NOT NULL DEFAULT 'main'(表单族键,
  version 在 (tenant_id, store_id, form_key) 内递增), version INTEGER NOT NULL,
  notice_version TEXT NOT NULL DEFAULT '', purpose TEXT NOT NULL DEFAULT '',
  marketing_prompt TEXT NOT NULL DEFAULT '', fields TEXT NOT NULL(DEFAULT '{}',
  JSON:schema_version + fields 数组 + consent_required), status TEXT NOT NULL
  CHECK (draft|published|disabled|expired), expires_at TEXT(NULL,RFC3339;
  published 且过期 → 提交侧按 expired 处理), published_at TEXT(NULL),
  created_by TEXT NOT NULL, created_at TEXT NOT NULL, updated_at TEXT NOT NULL`,
  `UNIQUE(tenant_id, store_id, form_key, version)`。
- `form_submissions`:
  `id TEXT PK(fsub_), form_id→forms, form_version INTEGER NOT NULL(提交时快照),
  tenant_id→tenants(=表单归属租户), contact_id→contacts, lead_id→leads,
  consent_id TEXT NOT NULL DEFAULT '(contact_consents.id), marketing_allowed 0/1(快照),
  source TEXT NOT NULL DEFAULT '', source_ref TEXT NOT NULL DEFAULT '',
  payload_sha256 TEXT NOT NULL DEFAULT '', created_at TEXT NOT NULL`,
  `UNIQUE(tenant_id, form_id, source, source_ref)`(幂等键)。
  payload 原文不入库(只有 sha256)——与票面模型一致。
- 索引:forms(tenant_id, status)、form_submissions(tenant_id, form_id, created_at)、
  form_submissions(contact_id)。

## fields JSON 固定契约(schema_version=1)

```json
{
  "schema_version": 1,
  "fields": [
    {"name": "name",  "required": true},
    {"name": "phone", "required": true},
    {"name": "wechat", "required": false}
  ],
  "consent_required": false
}
```

- 字段名固定枚举 {name, phone, wechat},不得重复、不得出现枚举外字段;
- name/phone 恒为必填(首版拍板,fields 里必须存在且 required=true);
- wechat 可选:含于 fields 则接受该键,否则提交该键 → 400;
- `consent_required`(可选,缺省 false)是给渲染端(落地页/T1)的交互契约:
  营销勾选框必须显式呈现、缺省不勾;服务端 consent 语义不因它改变
  (consent 行恒写,marketing_allowed 取勾选值,缺省 false)。
- 长度上限:name ≤100 rune,phone 归一化后 ≤32 且必须是 CN 手机号
  (11 位、1[3-9] 开头),wechat ≤64 rune,source ≤64 ASCII 标识符,
  source_ref ≤128 ASCII 标识符(复用 intake validKeyToken 语义)。

## API(Go server /api/v1)

### 公共(无商家登录;requireInternal,无会话)

| 端点 | 说明 |
|---|---|
| `POST /public/forms/{id}/submissions` | 校验表单 published/未过期(404=不存在或草稿;410=停用/过期)→ 限流(每 IP+表单 30/min,429)→ 白名单校验(400 逐项 details)→ 幂等(原 submission 200 duplicate)→ 短窗防重(200 duplicate_recent)→ `IntakeLeadInTx` 同事务三分类 + consent 行(submission id 作 source_submission_ref,channel=public_form,notice_version/purpose 从表单)+ form_submissions 行,一次 commit |

- 请求体:`{name, phone, wechat?, marketing_allowed?, source, source_ref}`;
  成功 201(重复 200):`{submission_id, contact_id, lead_id, consent_id, class,
  marketing_allowed, duplicate, notice_version, revoke_hint}`(revoke_hint = 成功页撤销渠道文案)。
- 接收租户 = form.tenant_id;header/body 租户参数结构性无效。
- 接收来源留痕:非空 source 建出/复用 source_refs 行,lead 获得来源/活动引用。

### 管理面(requireSession + ActionManageForms,owner 专属)

| 端点 | 说明 |
|---|---|
| `POST /forms` | 建草稿;version = 同族 max+1(首版=1);notice_version/purpose 允许草稿期留空 |
| `GET /forms` / `GET /forms/{id}` | 列表/详情(本租户) |
| `PATCH /forms/{id}` | 仅草稿可改(notice_version/purpose/marketing_prompt/fields/expires_at/store_id);已发布 409 |
| `POST /forms/{id}/publish` | 草稿→发布;校验 notice_version/purpose 非空(缺失 400)、fields 合法;置 published_at;此后不可变 |
| `POST /forms/{id}/disable` | draft|published→disabled(停用) |
| `GET /forms/{id}/schema` | 固定渲染/校验契约 JSON —— **碰一碰(T1)复用的唯一接口** |

## 复用契约(GET /api/v1/forms/{id}/schema 返回,owner)

```json
{
  "form_id": "frm_...", "form_key": "main", "version": 1, "status": "published",
  "schema": {"schema_version": 1, "consent_required": false,
    "fields": [{"name":"name","type":"text","required":true,"max_runes":100},
               {"name":"phone","type":"phone_cn","required":true,"max_runes":32},
               {"name":"wechat","type":"text","required":false,"max_runes":64}]},
  "consent": {"notice_version":"v1","purpose":"...","marketing_prompt":"...",
              "marketing_default": false, "revoke": "提交成功页展示撤销渠道文案…"},
  "submit": {"method":"POST","path":"/api/v1/public/forms/{form_id}/submissions",
             "idempotency_key":["source","source_ref"]},
  "limits": {"per_ip_per_form_per_minute": 30, "resubmit_window_seconds": 600}
}
```
