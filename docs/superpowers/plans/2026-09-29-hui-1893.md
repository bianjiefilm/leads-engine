# HUI-1893 销售工作台本地切片 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在已有销售工作台上补齐手工线索的负责人、许可、未知同步、跟进幂等和草稿按钮纪律，并锁住窄屏三条动作。

**Architecture:** 决策仍放在 `server/internal/workbench`。存储只为跟进幂等加一列，并为工作台读出负责人姓名和 Notify 回执。页面只渲染服务端事实，不提交草稿，不调用模型。

**Tech Stack:** Go、SQLite 迁移、Next.js、Vitest。测试用 `GOWORK=off`。

**Spec:** `docs/superpowers/specs/2026-09-29-hui-1893-design.md`

## Global Constraints

- 只改 leads-engine 这一工作树。不改 touch-engine、public-ai、GoBoost。
- 不伪造 Touch 提交，不把联合经营链标成完成。
- 不重写租户映射，不引入 shadcn，不重做 EcoTopNav。
- 无模型密钥不调用模型。意向文案只能是「真实模型未完成」。
- 不写 Billing PASS，不把内部成本显示成用户价格。`ordinary_crm_charge_cents` 保持 0。
- 未知同步不是 0，也不是「已跟进」。
- 无营销许可时响应不得出现「自动触达已成功」。
- 普通销售在类别、权限、人工确认三者缺一时不出现「创建服务需求草稿」。按钮若出现则禁用并说明原因。本轮不把草稿交给别的引擎。
- 端口只用 127.0.0.1:18270 和 127.0.0.1:18370。不碰 18101、18084、18120、18230、18330、18260、18360、8080、8081、5173，也不动 cloudflared。
- git add 指定文件。不 force-push，不合并 main。
