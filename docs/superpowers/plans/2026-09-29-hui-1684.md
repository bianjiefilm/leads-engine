# HUI-1684 意向分级收口 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 PR #19 已合入的规则分级上，补上夹具反例、缺凭证的 `not_completed` 尝试、商机页修正，以及高分不能外呼、私信或建单的证据。

**Architecture:** 规则仍由 `intentgrade.Score` 计算。模型尝试单独落在 `intent_model_attempts`，结论列恒空。商机详情页只调用已经存在的评分和修正接口。

**Tech Stack:** Go、SQLite、现有 Next.js 商机页、Vitest。`GOWORK=off`。

**Spec:** `docs/superpowers/specs/2026-09-29-hui-1684-design.md`

## Global Constraints

- 分级留在 PR #19 的 `intentgrade` 与 `/api/v1/intent-grades`。不改 `handler_service_draft.go`。
- 级别只有 `high`、`medium`、`low`、`insufficient`。分级界面和分级接口不出现未校准成交概率、置信百分比或「预计成交」。
- 没有模型凭证时判定保持 `not_completed`。不落模型级别，不编造引用、版本或任务号，不写 `PASS`。夹具来源是 `fixture`。
- 五条反例是强意向、普通问答、售后、缺数据、拒绝联系。没有凭证时不发起模型 HTTP。
- 销售在现有商机页修正或驳回。人工事实不被后一次 AI 快照覆盖。新消息或撤回让旧快照失效。没有计费客户端时费用保持 0，不重复扣。
- 高分也不能外呼、发私信或建订单。
- 租户 A 读不到租户 B 的快照。线索正文里的指令不能越权、不能改已存级别、不能触发外发。
- 不改 shuhai-guanlan、touch-engine、public-ai。没有 shadcn，不引入。
- Go 测试加 `GOWORK=off`。不占用 18101。本地服务先看 18230/18330，被占则用 18231/18331。结束前停掉自己起的进程。
- 报告写「真实模型未完成」。不写真人成交提升。
