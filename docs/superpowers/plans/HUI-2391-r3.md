# HUI-2391 R3 线索到矩阵的草稿交接 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在进程内把一次合法内容选定记成矩阵草稿引用，并在夹具回报后记下受限结果引用，而不发布、不扣费、不写线索。

**Architecture:** `server/internal/matrixhandoff` 自带夹具客户端和内存服务。规则在 `Service` 里。夹具只接收受限载荷或返回错误。文档、日志和通知由服务序列化，测试只调用这个包。

**Tech Stack:** Go 1.26，标准库。测试用 `GOWORK=off`。

**Spec:** `docs/superpowers/specs/HUI-2391-r3.md`

## Global Constraints

- 幂等键：租户 + 活动 + 资产 id + 内容版本 + 用途。同一键不改已存内容，不第二次调用夹具。
- 夹具载荷只有 `source_ids`、`asset_id`、`version`、`return_ref`。
- 电话、邮箱、CRM 档案、客户名单、消息正文拒绝且不存储。
- 意向分、销售角色、生产授权标志不能批准或执行发布。
- 无选中内容的顶栏跳转不建计划和草稿。
- `matrix_plan`、`matrix_item`、`external_post` 只附着在已有草稿上。未知触达、点赞、线索量保持 null，不得写成 0。
- 状态 `draft_recorded`，文案「已记下草稿引用」。不得出现「发布成功」或「白标经营链完成」。夹具成功不是 live receipt，也不是白标经营链完成。
- 跨租户行动者拒绝。同一提供者事件 id 不建第二条线索或草稿。
- 客户端错误后线索路径仍可用。`lead_writes`、`reply_bot_starts`、`charge_writes` 为 0，`charged` 为 null，`billing_passed` 为 false。
- `revoke` / `replay` / `edit` / `withdraw` 不恢复已撤销的发布许可。
- 日志和文档不含消息正文。通知只有 id。
- 无私信授权的渠道是 `unavailable`。不宣称八平台私信接入。
- 服务商 `NOT_VERIFIED`，计费 `NOT_VERIFIED`，生产 `NOT_AUTHORIZED`，真人采用 `UNKNOWN`，浏览器 `NOT_RUN`。
- 不改独占写集以外的文件。不绑定 18084、18120、8080、8081、5173、18101–18106。

### Task 2: 实现夹具和服务

**Files:**
- Create: `server/internal/matrixhandoff/fixture.go`
- Create: `server/internal/matrixhandoff/handoff.go`
- Test: `server/internal/matrixhandoff/handoff_test.go`

**Interfaces:**
- Consumes: Task 1 的测试调用。
- Produces:
  - `NewFixture() *Fixture`，`SubmitDraft(Payload) (Ack, error)`
  - `New(Client) *Service`
  - `Select(Selection) (Draft, error)`
  - `Jump(*Selection) (JumpResult, error)`
  - `ApplyEvent(Event) (EventResult, error)`
  - `Document(id) (string, error)`，`Notice(id) (Notice, error)`，`Audit(id, body) string`，`Logs() []string`
  - `Effects() Effects`，`LeadPath(LeadPath) LeadPath`
  - `PublishPermitted(tenant) bool`，`PublishRevoked(tenant) bool`
  - `Evidence() Labels`，`AssessChannel(Channel) ChannelAssessment`，`ClaimsEightPlatformDM() bool`
  - 哨兵错误 `ErrForbidden`、`ErrCrossTenant`、`ErrNoContent`、`ErrNotLegal`、`ErrClient`、`ErrEventID`、`ErrEventKind`、`ErrNotFound`

- [x] **Step 1: Write minimal implementation**

`Fixture.SubmitDraft` 在错误时不保留载荷。`Ack.Published` 和 `Ack.Outcome` 由服务忽略。

`Select` 先拒绝禁字段和非 token 来源，再拒绝跨租户，再要求 `Legal` 和完整资产身份。命中已有键时直接返回原草稿。否则提交受限载荷；客户端错误时不插入草稿，也不把 `leadPathUsable` 设为 false。新草稿的发布旗标和 live receipt 全为 false。

`Jump(nil)` 或没有资产 id 时返回空结果。`ApplyEvent` 按规格顺序校验；重复事件 id 在改状态之前返回。`revoke` 写入撤销锁并清除 allow。结果事件只在草稿已存在时写入引用和非空指标指针。

`Document` 序列化草稿、当前效应和五条证据。`Notice` 和 `Audit` 只有 id。`Effects.Charged` 保持 nil。
