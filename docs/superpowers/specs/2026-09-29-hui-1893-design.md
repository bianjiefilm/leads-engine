# HUI-1893 销售工作台本地切片设计

日期：2026-09-29。这是架构级切片，但只补 origin/main 上已经合入的工作台还缺的诚实缺口。总指挥已经拍板，下面没有待确认问题。

联合经营链 Touch → 真实 Notify → 同一条留资 → 首次跟进 本轮不做。不要伪造 Touch 提交，也不要把不同 seed 拼成一条经营链。本文件不把这张票标成整票完成。

## 不改什么

- 不重写 CRM，不改租户映射（HUI-2316 已合入）。
- 不改 touch-engine、public-ai、GoBoost、产品图、数字人、AiCut。
- 不引入 shadcn。这个应用没有该依赖。不重做 EcoTopNav。
- 不调用模型，不编造成功，不把内部成本写成用户价格，不写 Billing PASS。
- 不把操作轨迹写成真人满意度、采用率或成交提升。
- 下一步仍以人手工设置的时间和动作为准。AI 分数、意向等级、模型建议都不能自动外呼、自动发消息、自动创建订单。
- 已有队列、范围、金额分列、渠道跟进不升格成短信、售后不推进商机，这些行为用现有测试锁住，不改断言正文。

## 已有行为（锁住）

`server/internal/workbench` 和 `GET /api/v1/workbench`、`GET /api/v1/leads/{id}/timeline`、`POST /api/v1/leads/{id}/follow-through` 已经做了这些事：

- 手工下次时间压过建议；分数不能把 `auto_call`、`auto_message`、`create_order` 设为真。
- 销售只看分配给自己的行；owner 看本租户；另一租户的工作台读不到这条线索，列表也不带电话。
- 没有下一步的活跃商机留在 `needs_schedule`，不消失。记下跟进后线索仍在。
- 手工联系人的来源渠道是「手工录入」。
- 客户成交、派诺服务订单、平台工具消费分开，未知金额是 null，不是 0，也不加总。
- `ordinary_crm_charge_cents` 保持 0。这是「不逐条扣费」的既有字段，不是用户价格，也不是 PASS。
- `show_service_draft` 仍表示类别是 `creative_service`。门店经营商机为假。

## 本轮要补的缺口

### 1. 手工线索在工作台上可读

本租户、`source_type=manual` 的线索出现在调用者有权看见的队列里。每一行同时给出：

- 来源：沿用已有 `source`（手工录入及时间）。
- 负责人：成员 `display_name`。没有姓名但已分配时写「已分配」，不写成员 id，不写电话。
- 未分配：`assignment_reason` 为「待分配」。销售和 agent 仍然看不见未分配给自己的行。
- 允许的联系方式：只来自已存储的同意。营销短信或电话许可才列出 `sms`、`phone`。渠道内回复许可才列出 `channel`。没有许可就是没有方式，不把库存电话当成许可，列表仍不出现电话号码。
- 下一步：已有手工时间用手工；否则是「不是模型输出」的安排建议。

### 2. 跟进留下，并能再约

`follow-through` 写入后，再次读取时间线和工作台仍能看见这条记录，并可以带下一次时间。活跃商机没有手工下一步时继续出现在待安排。

同一调用者、同一线索、同一备注、同一规范化下次时间、同一渠道、同一「是否完结本次」再次保存，必须返回原来的 `follow_up_id`，不得再插入一行。不同备注仍是另一条事实。完结戳沿用既有「首次戳保留」。重放不关闭后来才出现的其他跟进。

幂等键放在新列 `follow_ups.dedupe_key`，租户内唯一（空键不参与）。不改既有跟进表的其他列语义。

### 3. 同步未知

`statuses.received` 继续表示本 CRM 里已经有这条线索，既有测试保持不变。它不是外部回执。

另给 `sync`，只有一个字符串 `crm`：

- 没有 Notify 收件回执：`unknown`。界面写「同步：未知」。
- 有挂在这条线索上的 `notify_inbox.receipt_json`：`received`。界面才可以写「CRM已接收」。

`sync` 没有数量字段。未知不得写成 0，不得写成「已跟进」。`followed` 仍只看已完结的跟进事实。缺事实的成交和回款继续不显示为已成交、已回款。

### 4. 没有营销许可就没有自动触达成功

工作台响应在没有营销许可时，正文不得出现「自动触达已成功」。有许可但没有发送回执，同样不得出现这句。本切片不发送，因此工作台组装结果永远不带这句。说明文案用「没有营销许可」或「没有触达回执」，自身不含那句成功话。

### 5. 服务需求草稿

普通门店销售（`sales` 和 `agent`）不出现「创建服务需求草稿」，除非类别是 `creative_service`、调用者能更新该商机、并且已有人工确认三件同时成立。

按钮如果出现但条件不全：不可用，并写出原因。本轮按钮即使可用也不请求 GoBoost 或其他引擎，不新增交接行。原因要说明本轮不提交草稿。

`show_service_draft` 仍只表示类别。页面改看 `service_draft.present` 和 `service_draft.enabled`。

### 6. 意向

没有模型密钥就不调用模型。工作台和线索页的意向一行固定为「真实模型未完成」。安排建议不得标成模型输出。

### 7. 窄屏

约 390px 仍能走完「查看新线索 → 记跟进 → 安排下一次」。三件事都留在页面上，不隐藏。视口不超过 720px 时操作纵向排开，这包含 390px。浏览器若起不来或登录走不通，组件测试锁住这条布局，报告写浏览器走查 UNKNOWN。接口测试不算浏览器通过。登录只沿用仓库已有测试会话；不起身份桩冒充平台 SSO，不占用 18101。

## 方案

推荐方案是扩展现有纯决策和现有三个路由。队列真源仍在 Go，页面只渲染。否决另起一套销售台，也否决在本仓伪造跨系统经营链。

## 接口附加

工作台线索行和时间线增加：`owner_label`、`assignment_reason`、`allowed_contacts`、`sync`、`outreach_notice`、`model_advice`。商机行增加 `service_draft`：`present`、`enabled`、`reason`。

`POST .../follow-through` 第一次仍是 201。相同事实重放是 200，`replay` 为真，`follow_up_id` 与第一次相同。自动化三个开关仍为假，计费字段仍是既有的 0，响应不出现 PASS。

## 测试

- Go 纯函数：幂等键稳定、同步未知不含 0 和「已跟进」、无许可无成功句、销售在未确认时不出现草稿按钮、负责人与允许联系方式。
- HTTP：手工线索的来源、负责人、待分配、范围、租户隔离、重放不产生第二行、刷新后记录仍在、活跃商机仍待安排、同步未知、无成功句、草稿不落交接表。
- Vitest：390px 三个动作都在且纵向；同步文案；草稿控件不提交；计费文案不是价格也不是 PASS；换租户仍丢掉另一租户队列。

## 自检

- 没有 TBD。联合链明确不做。
- `received` 与 `sync.crm` 不是同一个事实，互不改写。
- 销售隐藏草稿，和 owner 看到禁用按钮，不矛盾：前者是「不出现」，后者是「按钮在但不可用」。
- 范围只覆盖本仓工作台切片，一个计划可以做完。
