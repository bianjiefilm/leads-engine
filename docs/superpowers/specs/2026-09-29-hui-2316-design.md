# HUI-2316 租户映射稳定化

日期：2026-09-29。基线 SHA：`d085f44051ff560a27f4a4840af2dffeeb9ccdc1`（origin/main，已包含 PR #29 / `f556b63`）。

## 问题

`storeTenantForEvent` 先按事件里的租户 ID 查本库。查到行就直接用；查不到才读 `LEADS_TENANT_BINDINGS`。`GetTenant` 的任何错误都当成不存在。`handleNotifyIngest` 在幂等查找、线索写入和撤销之前把 `delivery.TenantID` 改成这次解析出的目标。

反例：源 S 在本库不存在，绑定 S→A，首条落入 A。之后插入同 ID 的本地租户 S，配置没改，解析却改走 S。旧事件重放和撤销离开 A，跟进摘要变成 0。这是代码条件风险，不是已证实的生产串租户。

## 已核对的身份边界

`server/internal/identity` 只解析会话到 principal。本仓库没有平台租户目录，本票不新增全局人/租户中心，也不新增第二套功能开关。

因此「本库有同 ID 行」不是平台统一租户契约。没有显式绑定时，同 ID 直通只表示：这个 ID 就是本库 `tenants.id`，而且没有任何绑定认领它。依据记为 `leads_primary_key`，版本记为 1。一旦存在显式绑定，本地同 ID 行不能推翻它。

## 映射

一条映射是：

- 来源 app（未写时为 `*`）
- 来源命名空间（未写时为 `*`；Notify 入库存 `notify`）
- 外部 tenant
- 目标 tenant
- 版本（未写时为 1，必须 ≥ 1）
- 依据：`operator_binding`（配置）或 `leads_primary_key`（本库主键直通）

环境变量，逗号分隔，全有或全无：

```
external=target
external=target@version
source_app/source_ns/external=target@version
```

同一 `(app, ns, external)` 重复、通配和精确条目重叠、空段、缺 `=`、源和目标相同、版本非法：整份绑定丢弃，不保留前面的「有效」条目。接收和跟进摘要返回 503，不改路由。

## 解析

新的 source ref 才解析当前配置。顺序：

1. 数据库错误直接失败（500），不改走另一条绑定，也不当成 404。
2. 该来源键已有落库目标，且当前绑定指向同一目标：继续用该目标。后出现的本地同 ID 行不参与决定。
3. 已有落库目标，但当前绑定指向别处，或绑定被删掉而落库目标不是本库主键直通：新的 source ref 拒绝（409），并给出迁移提示。
4. 没有落库记录时：只有绑定且目标存在，并且本地还没有这个源 ID（或目标就是该 ID）才接受。本地已有 S 又把 S 绑到别处：拒绝。
5. 没有绑定且本库有该主键：`leads_primary_key`。
6. 绑定目标不存在：404，提示去开通目标或改正配置，不要靠新建本地 S 改路由。

已存在的 event id 在解析之前按来源身份查找。正文哈希相同则返回原回执；不同则 409。不按当前配置另开一行。

同一来源的 source ref 已有 inbox 或撤销行时，更高 `source_version` 和撤销沿用该行的目标，即使当前配置已经冲突。避免撤销丢失。

`FetchRecord` 始终用来源侧 tenant（外部 ID）。线索、consent、source ref、inbox、撤销写入用目标 tenant。

## 落库

`notify_inbox` 与 `notify_revocations` 增加来源命名空间、来源 tenant、映射目标、版本、依据。`tenant_id` 仍是 CRM 目标，并保持外键。

来源快照在原有活动字段外写入同一组映射事实。跟进摘要读到的活动引用不变。

幂等键追加唯一索引 `(source_app, source_ns, source_tenant_id, profile_event_id)`。旧的目标租户唯一键保留。

跟进摘要：

- 该外部 tenant 的已落库目标只有一个时，用那个目标，不重新猜测。
- 多个目标时 409，不返回任何 lead id。调用方可以带 `source_app` 只读一个来源。
- 还没有落库记录时，走和接收相同的解析规则。

## 兼容与迁移

升级只加列。旧行把 `source_tenant_id` 和映射目标回填为当时保存的 `tenant_id`，依据为 `legacy_stored_tenant`，版本为 0。不搬迁线索、联系人、同意或撤销。

旧行的来源 ID 若当初被改写成了目标，无法从账本恢复。重放仍按 `(source_app, event_id)` 的遗留行认领，避免在另一个租户再写一条。新事件会写上来源 ID，之后不再依赖这条回填。

不提供自动搬家。要把历史从 A 改到 B，必须另做迁移，同时改 leads、contacts、consents、source_refs、notify_inbox、notify_revocations 的 `tenant_id`。本票拒绝只改环境变量造成的漂移。

操作提示（接口 `hint` 同义）：

- 绑定整份无效：改成每个来源键一行，重启。已经落库的不移动。
- 本地已有 S 又配置 S→A：删掉该绑定则新事件留在 S；若 S 没有 CRM 数据，先删除空的本地 S，再保留绑定。不要指望新建同 ID 租户来改路。
- 目标不存在：先开通目标，或改正绑定。不要创建同 ID 的源租户。
- 已落库目标与当前绑定不一致：恢复原绑定，或做上面的成套迁移。重放和已有 source ref 的撤销仍打在原目标。

## 明确不做

不等 HUI-1893 的浏览器链，不建第二条总 Gate，不迁移生产客户，不发送营销，不改 touch-engine。去重仍只在目标租户内按现有 intake 规则进行。两个来源映到两个目标时，相同手机号不合并；映到同一目标时，在该目标内去重。
