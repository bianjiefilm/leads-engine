# HUI-1688 统一接待核心 V1 设计

日期：2026-09-27。票面即范围。指挥官已拍板，本文件只记录实现选择。

## 目标

在现有 leads-engine 增加接待模块。匿名访客用受限会话，不注册 principal，不进营销池。知识、会话、转人工、线索留资都只在本租户。数字人（HUI-20）只拿窄呈现契约。

## 做法

`FEATURE_RECEPTION` 默认关闭，关闭时路由不注册。打开后：

- 商家 H5 入口是 `reception_widgets`。公共请求的租户只来自入口归属，请求头和正文里的租户字段无效。
- FAQ 是 `knowledge_sources`：版本、更新时间、启用、撤回。回答只引用启用且未撤回的条目，并在回复上留下 source id、version、updated_at 与不足项。
- 人设文案只存在入口上，不拼进回复正文，也不能当价格、库存、订单事实。
- 价格、库存、订单状态只读 `FactBook`。未注入、超时、缺字段、过期（含没有到期时间）都澄清或转人工，不把 FAQ 里的数字当实时交易事实。退款、改单等写入意图直接拒绝，本票没有订单写接口。
- 访客原文和 FAQ 正文都是不可信数据。命中指令注入只记 `untrusted_input`，不改变租户、权限、模式或工具。
- 会话保存 mode（ai / assist / human）、owner、epoch、version。人工接管和明确转回 AI 都会把 epoch 加一，并作废旧 epoch 上尚未发送的回复。文本和音频的可发送标记同一条件：当前 epoch 且 status=approved。
- 回复有稳定 id。生成、批准、已发送分列记录。访客 `client_msg_id` 和发送回执重复时不新增回复、线索或用量行。
- 用量写入 `reception_usage`，`live_charge` 有 CHECK 恒为 0。本票不配置、不调用任何扣费或外部模型 URL。模型回调失败时 FAQ/事实仍可回答；没有依据就不编造，人工回复照常。
- 结案不建线索。只有明确目的 `sales_followup` 且允许联系时，才走既有 `IntakeLeadInTx`。营销同意默认否。跟进复用 `follow_ups`。
- 工作台列表给出负责人、待处理原因、人工待办、下一次跟进，供 HUI-1893 读取。呈现接口只含 session 引用、语言、版本、已记录事件、回复文本和可否发送。不含联系方式、知识全文、人设原文、长期 token。

## 测试

服务端测试覆盖两租户隔离、FAQ 回源、过期/缺失价格不编造、接管后旧回复文本和音频都不可再发、退出重进同一会话、重复消息不重复回复/留资/用量、H5 接待到人工再到授权跟进。真实扣费插入必须被 CHECK 拒绝。
