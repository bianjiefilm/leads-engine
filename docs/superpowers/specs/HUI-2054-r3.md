# HUI-2054 R3 白标隔离剩余缺口

日期：2026-09-30。总指挥已经拍板。本文件只补 PR #26（`aa6fa99`，合入 `ed05f227d52dd94e0eab0355321eb140a5ea87c2`）还没被测试锁住的缺口，不回退它。

品牌是展示和来源。租户才是联系人、线索、商机、跟进和导出的权威。品牌不代替租户。

Touch → 真实 Notify → Leads 的白标经营链本轮保持 NOT_VERIFIED。夹具接收器不是这条链的证据。界面不出现「白标经营链完成」「白标经营链已完成」「自动触达已成功」「销售已收到」。工作台仍写「联合经营链未完成」。

## 不改什么

- 不重做 PR #26 已有的隔离、导出和暂停。
- 不新开租户映射表。HUI-2316 已完成。来源标签、品牌 id、活动 id 只留在来源行，不改 `contacts.tenant_id`。
- 不改 HUI-1893 的诚实文案，不改 HUI-1688 的接待轮次和版本，不把成员 id 显示成姓名。
- 不把导出做成 SQLite 文件拷贝。旧的 CSV 和 admin JSON 导出保留。
- 不引入 shadcn。不改 touch-engine、shuhai-guanlan。
- 不在凭证缺失时调用真实 Notify。不占用 18101，不绑定 18084、18120、8080、8081、5173。
- 计费 NOT_VERIFIED。生产 NOT_VERIFIED。真人采用 UNKNOWN。

## 本轮要锁住的行为

同一进程里，主体甲同时是租户甲和租户乙的成员。只换 `X-Tenant-ID` 时，甲读不到乙的联系人、线索、商机和跟进；用乙的联系人 id 在甲的租户里建线索、商机或跟进会被拒绝。

同一手机号或同一邮箱在两个租户各有一条联系人。它们不合并，也不写成平台主体。

请求体里的租户字段如果等于品牌 id，仍然落在成员租户。来源标签或活动 id 即使写成另一个租户的 id，也不改变落库租户。来源行记下品牌、标签和活动，冲突更新时不改 `tenant_id`。

没有 support 或 operation 委托的渠道管理员，不能从 CRM 接口读到联系人明文。

租户甲的导出只有甲的行和甲的同意历史，含撤回原因。不含乙的行、采购价和平台令牌。下载再次核对请求者；另一个负责人和换了租户头的同一主体都下不了甲的任务。响应是 JSON，不是数据库文件。

租户暂停和品牌暂停分开。恢复不带回已禁用的成员、已撤回的营销同意和已撤销的委托。额度不足可以停掉新的付费 AI，不能藏起已有联系人和跟进。

## 测试

- `TargetTenant` 拒绝用品牌、来源标签或活动改租户。
- HTTP 用同一个主体覆盖隔离、导出、暂停和额度。
- Vitest 锁住隔离页文案，并拒绝把完成句渲染成经营链。
