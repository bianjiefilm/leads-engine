# HUI-1688 接待收口设计

日期：2026-09-29。总指挥已拍板。本文件只补 PR #17 和 PR #28 还没证明的缺口，不重做已经合入的 FAQ、无依据不报价、人工接管和受权跟进。

## 不改什么

- 不重写 `TestReceptionH5PathIsolationAndNoDoubleCharge`、`TestReceptionTakeoverBlocksUnsentDraft`、`TestReceptionAssistApproveThenSend`、`TestReceptionReleaseInvalidatesUnsentHumanReply` 和 `TestReceptionLiveChargeRejected`。
- 不新建第二套知识库、会话或 CRM。不改 `shuhai-guanlan`、`touch-engine`、`public-ai`。
- 租户映射只用已经合入的 HUI-2316。本票不新增绑定，也不改 `tenantmap`。
- 不实现退款和订单写入。`POST /api/v1/reception/refunds` 继续不存在。
- 数字人呈现仍由别人做。本票只保持窄契约，不等待呈现端。
- `reception_usage.live_charge` 继续恒为 0。真实费用只可能出现在平台任务回执里，不能靠把这一列写成 1 来冒充扣费。
- 页面仍是现有 Next.js 接待页。仓库里没有 shadcn，不引入组件库，不改 Vue 或 uni-app。

## 一条会话上的模式链

同一条进行中的会话按这个顺序走，每一步都是明确请求：

1. 挂件以 `ai` 打开。有依据的问答由服务端直接发送。回复记下当时的 `epoch` 和 `session_version`。
2. 客服 `POST /sessions/{id}/assist`，正文必须带当前 `epoch`（小于 1 为 400）。只接受当前 `ai` 轮次。成功后 `mode=assist`，`epoch` 和 `version` 各加 1，未发送回复改为 `superseded`，事件类型为 `assist`。已经是协助且 epoch 相同则不重复加轮次。人工模式下拒绝。
3. 协助模式只生成草稿。客服批准后才可以发送。批准不等于接管。
4. 客服 `POST /sessions/{id}/takeover`。`epoch` 再加 1。旧轮次里未发送的 AI 文本和音频都不再可发。已发送的历史可以留在访客记录里，但呈现契约里 `deliverable.text` 和 `deliverable.audio` 都为假，因此不会再念一遍。另一个人用旧 epoch 抢接得到 409，epoch 不变。
5. 人工模式下访客再发消息只记打断，不生成 AI 回复。只有当前接管人（或店主）能写人工回复。
6. 交回 AI 只来自 `POST /sessions/{id}/release`，而且当前模式必须是 `human`。成功后 `mode=ai`，负责人清空，`epoch` 再加 1，未发送的人工回复作废。此后人工回复接口拒绝，下一条有依据的访客消息只由 AI 回答。两边不能同时答复。
7. `POST /sessions/{id}/close` 只把状态改成 `closed` 并增加 `version`，不建线索。结案后访客消息、人工回复、接管、协助都拒绝。

客服是带本租户 `agent_grants` 的 `agent`。销售是 `sales`。店主仍独占挂件和知识配置。客服和销售可以看见本租户全部进行中的接待会话，以便接手和受权留资；这不放宽 CRM 联系人、线索的原有分配隔离，也不让销售抢走别人已经拿住的人工轮次。无授权的客服仍被拒绝。

## 依据、注入和营销池

- 价格、库存、订单状态仍只来自未过期的 FactBook。文档和人设里的数字不能当实时事实。
- 商家文档和访客输入都不可信。提示注入不能读到另一个租户的知识，不能改成员角色，不能打开退款或其它未批准写入。
- 匿名访客只保留钥匙摘要。打开会话和普通问答不增加 `members`，也不建联系人或线索。
- 线索仍要 `sales_followup`、允许联系、姓名、电话和告知版本。售后和一般问答拒绝。请求里的 `marketing_allowed: true` 忽略，落库同意始终为否。没有受权线索不能跟进。
- 会话还没有负责人时，建线索的人成为联系人和线索的负责人。已有负责人时不改写。

## 模型

有依据的 FAQ 回答才可以请求模型，而且只为了留下平台任务。发给平台的 `params` 只有语言、已经确定的依据正文和引用 id，没有访客原文、电话、人设全文、别的租户知识或长期令牌。模型返回的文字不进入访客正文，避免改写价格。

三键齐了才调用：`PLATFORM_TASK_BASE_URL`、`PLATFORM_TASK_TOKEN`、`PLATFORM_TASK_ACCOUNT_ID`。缺任何一键就不发请求，回答仍用依据正文或原有的澄清、转人工。每条回复最多一条 `reception_model_calls`：

- 没完成真实任务：`billing_verdict=not_completed`，`cost_cents=0`。可以没有 `task_id`。
- 平台任务到达 `SUCCEEDED` 且有 `task_id`：`billing_verdict=recorded`，`cost_cents` 为这次声明的 1 分（0.01 元）。这不是账单上的 PASS 标记。
- 表约束拒绝 `PASS` 以及 `not_completed` 带正成本。

迟到：模型返回前如果 epoch、模式或结案状态已经变了，回复写成 `blocked`，不发送，文本和音频都不可发。同一次幂等键不提交第二次任务。同一 `client_msg_id` 重放不新增用量，也不再调用模型。

接口缺失、过期、超时仍澄清或转人工。模型超时或失败时，有依据的正文照发，裁决保持 `not_completed`。

## 呈现契约

`GET .../presentation` 只含 `session_ref`、`language`、`version`、`events`、`replies`。回复只含 `reply_id`、`version`、`text`、`language`、`deliverable.text`、`deliverable.audio`。事件只含 `type` 和 `epoch`，类型是 `assist`、`takeover`、`release`、`interruption`。不放客户资料、知识全文、人设或长期令牌。

## 页面

工作台显示当前身份（客服、销售、店主）、轮次和版本。`ai` 时提供「改为协助」。旧轮次未发送回复写明文本和音频都不能再发送。没有完成的模型任务显示「文本降级，真实模型未完成」；有任务 id 时只显示任务和成本分数，不显示 PASS。访客页在结案后显示「已结案」。

## 验收

浏览器分别用访客、客服、销售走完：AI 接待、协助批准、接管、交回 AI、结案，并在销售授权后留下线索和跟进。A/B 租户不能互读。本机没有平台任务三键时，报告写「真实模型未完成」，不得把这条标成 Billing PASS。
