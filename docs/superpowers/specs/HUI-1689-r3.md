# HUI-1689 R3 沙箱调度

日期：2026-09-30。总指挥已经拍板。本轮只在 `server/internal/sopreach` 里加沙箱调度，不改已经合入的确认门。

`Decide` 继续负责提醒、草稿和人工确认。无人值守默认关闭。余额和 AI 分数不能打开自动发送。确认之后仍然不是送达。本轮不回退这套行为，也不把它接到新的 HTTP 路由上。

## 不改什么

- 不改 `decide.go` 的确认前才允许进入发送门。已有测试保持原样。
- 不改 matrixhandoff、crafthandoff、reception、lightcopy、crmtenant、store、web、httpapi、migrations、`go.mod`、`go.sum`。
- 不引入 shadcn。不发送真实短信、邮件或企微。不占用 18101，不绑定 18120、18084、8080、8081、5173。
- 浏览器走查本轮不跑。
- 夹具不是正式渠道。不写已送达、已回复或自动触达已成功。

## 调度

默认不自动发送。明确打开进程内自动开关，并且调用方同时给出无人值守等级和显式开关时，才可以把动作放进队列。放进队列不是发送。之后若自动开关被关掉，这条旧动作作废，不再发出。

人工路径固定为：提醒，然后草稿，然后由角色 `authorized_test` 确认。缺提醒、缺草稿、角色不对，都不提交。确认使用草稿里保存的正文、渠道、用途、活动、联系人、租户和内容版本。确认时不能换成另一段正文。

确认和自动放行都只向调用方给出的夹具地址发 HTTP POST。不读取响应正文。只有 HTTP 200 表示提交已受理。201、500、网络失败都不是受理。受理后的送达状态是 `unknown`。夹具合同没有回执字段，响应里即使出现回执或送达字样也忽略。每次结果都带 `正式渠道未验证`。

人工接管、退订、撤销、静默时窗（`InsideWindow == false`）或频控（`RateLimited == true`）会在放行时再次检查。命中则停掉那条已排队的自动动作，不提交排队时的旧正文，也不提交放行时临时换上的正文。停掉之后，即使这些标志被清掉，旧动作仍然不发。

这些条件同样挡住确认提交：退订、撤销、静默时窗、频控。人工接管只停自动动作；有权测试角色仍可确认当前草稿，确认走夹具，不带出已停掉的自动正文。

重复回调不再次 POST，也不记账。未知消息先按租户查找原消息；找不到就不创建发送。同一回调再次出现仍然不创建。跨租户的确认、放行和回调都拒绝，不把别的租户的草稿或原消息当成命中，也不借机把原动作停掉。

营销许可看同意记录上的活动，不看联系人还出现在哪个活动里。同意在活动甲，联系人出现在活动乙，不能当成乙的营销许可。跟进同意也不能当成营销同意。

## 证据

沙箱始终给出：

- `service_provider=NOT_VERIFIED`
- `billing=NOT_VERIFIED`
- `production=NOT_AUTHORIZED`
- `human_adoption=UNKNOWN`
- `charge_writes=0`
- `billing_passed=false`
- `provider_calls=0`

夹具 POST 不是供应商调用，也不是扣费。`billing_passed` 不得因为 HTTP 200 变成真。
