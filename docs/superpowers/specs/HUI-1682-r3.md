# HUI-1682 R3 当前线索场景到专业工具的夹具交接

日期：2026-09-30。总指挥已经拍板。本轮只新增进程内包 `server/internal/crafthandoff`。不挂 HTTP，不落库，不改既有短文案路径。

`lightcopy` 仍是场景内短文案的失败关闭路径：没有真实模型就拒绝生成，确认也不等于发送。本包不导入、不替换、不放宽它。

## 不改什么

- 不改 `lightcopy`、`matrixhandoff`、`crmtenant`、handlers、store、web、httpapi、migrations、`go.mod`、`go.sum`。
- 不引入 shadcn。不改 leads 的 web UI。
- 不绑定 18120、18084、8080、8081、5173。不把 `127.0.0.1:18101` 当获客桩。
- 不调用在线 GoBoost、产品图、数字人或 AiCut。夹具引用不是这些工具的在线会话。
- 不写「自动触达已成功」，也不写「白标经营链完成」。
- 服务商 `NOT_VERIFIED`。计费 `NOT_VERIFIED`。生产 `NOT_AUTHORIZED`。真人采用 `UNKNOWN`。
- 浏览器不跑，记 `NOT_RUN`。

## 短回复

保存短回复时，只有调用方同时标成已选和已授权的事实能进入草稿。未选事实一律丢掉。

短回复事实只接受这四个键：`scene`、`question`、`offer`、`next_step`。其它键，以及已选但未授权的事实，拒绝整次保存，不留下半份草稿。

电话、邮箱、CRM 画像、内部销售备注（`phone`、`email`、`crm_profile`、`profile`、`sales_note`、`internal_note`、`internal_sales_note`）即使被标成已授权也拒绝。事实值里出现邮箱或连续 8 位以上数字，同样拒绝。

未授权画像拒绝整次保存。已授权画像不写进短回复正文，也不单独构成一条短回复。

保存之后：未发送、未发布、没有营销许可、没有启动回复机器人。草稿盖「真实模型未完成」。保存本身不产生夹具，也不增加项目数。

## 复杂制作

复杂制作一次只接受一个目标：`goboost`、`product-image`、`avatar`、`aicut`。`product_image`、`digital_human` 和其它名字都拒绝。那些名字仍属于 lightcopy 的失败关闭交接，不能在这里变成夹具成功。

成功时返回同一条夹具引用。`live_session` 为假。夹具不是在线会话。

交接载荷只有三个字段：`source_lead_id`、`version`、`payer_ref`。没有电话、邮箱、CRM 画像、内部销售备注或画像。请求里带了这些材料就拒绝，并且不记项目。付款方引用本身如果是电话或邮箱，也拒绝。已授权画像可以出现在请求里，但不得进入载荷或夹具引用。

同一租户、同一线索、同一版本、同一目标返回同一个 handoff id 和同一个夹具引用。重复点击不增加第二个项目，不增加第二笔记账。`provider_calls` 保持 0，`charge_writes` 保持 0，`billing_passed` 保持 false。换一个付款方引用也不另开项目，载荷仍用第一次的付款方引用。

另一个租户读草稿、手改、撤销或发起交接都拒绝。

权限撤销之后，新的交接拒绝。已经保存的草稿还在，正文不变。

目标失败不记项目。草稿仍可手改。手改不发送，不启动回复机器人，也不把正文写进载荷。

夹具记下的生成成功不是「已发送」，不是「已发布」，也不是营销许可。结果仍盖「真实模型未完成」。

未提供的费用是未知，标签为 `unknown`，JSON 为 null，不是 0。明确给出的 0 仍是 0，但仍然不记账，`billing_passed` 仍为 false。

## 测试

在 `server/` 执行：

`GOWORK=off go test ./internal/crafthandoff/ -count=1`

该命令只证明进程内草稿、隔离、幂等和夹具边界。它不是服务商、计费、生产或真人采用的通过证据。
