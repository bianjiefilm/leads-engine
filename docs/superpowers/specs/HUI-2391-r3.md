# HUI-2391 R3 线索到矩阵的草稿交接

日期：2026-09-30。总指挥已经拍板。本包是进程内的 Leads → 矩阵草稿引用，不是第二个发布器，也不是第二个自动回复机器人。

线索、会话和跟进仍由 Leads 持有。矩阵只由本包里的夹具客户端代表。本包保存一份草稿引用，以及夹具稍后回报的结果引用。它不发布、不发私信、不扣费、不写线索。

夹具成功不是线上矩阵回执，也不是「白标经营链完成」。进程内记忆会随进程结束消失。没有迁移，重启不恢复草稿。这不是矩阵服务已接通。

## 不改什么

- 不重做 HUI-1681、HUI-1688、HUI-2054、HUI-2316。
- 不改 `go.mod`、`go.sum`、迁移、`httpapi`、`crmtenant`、`store`、web。
- 不导入在途包，不挂 HTTP，不引入 shadcn。
- 不调用真实 Notify、微信或线上矩阵。不绑定、不占用 18084、18120、8080、8081、5173、18101–18106。
- 不宣称八平台私信已接入。
- 服务商 `NOT_VERIFIED`。计费 `NOT_VERIFIED`。生产 `NOT_AUTHORIZED`。真人采用 `UNKNOWN`。浏览器 `NOT_RUN`。
- 本包不把工程结论写成 PASS。

## 草稿

在一个租户里选定一份已经存在的合法内容资产，产生一条矩阵草稿引用。幂等键是租户、活动、内容资产 id、内容版本、用途。同一键再次进入时返回同一个草稿 id，不改已保存的来源 id、资产、版本、用途和回跳引用，也不再调用夹具。

交给夹具的载荷只有来源 id（线索、会话、跟进）、资产 id、版本，以及受限回跳引用 `ret_` 加草稿 id。回跳引用不含线索 id，也不含电话、邮箱、档案或客户名单。

下列字段一旦出现就整次拒绝，夹具不被调用，存储和日志里都没有这些值：电话、邮箱、完整 CRM 档案、客户名单、消息正文。来源 id 若不是空或 token，同样拒绝。

意向分、销售角色、调用方声称的生产授权，都不是社交发布权。传入它们不会批准发布，也不会执行发布。

没有选中内容的顶栏式跳转不建营销计划，也不建草稿。不合法、缺少资产、版本小于 1，都不建草稿。两个租户各自合法选定同一资产 id 时，草稿不共用。

草稿状态是 `draft_recorded`，文案是「已记下草稿引用」。状态和文案不得包含「发布成功」或「白标经营链完成」。夹具即使把回执标成已发布或带上这两句，也不得写进草稿。`fixture_accepted` 只表示夹具收下了引用。`live_receipt`、`chain_complete`、`publish_approved`、`publish_executed` 保持 false。

## 结果、权限、失败

夹具稍后可以回报 `matrix_plan`、`matrix_item`、`external_post` 的受限引用。引用必须是 token，只写到已有草稿上。对不上的结果不新建草稿，也不新建线索。本包不因此创建营销计划。

触达、点赞、线索量用空值表示未知。未知不得写成 0。调用方明确给出的 0 可以保持 0。同一提供者事件 id 的再次进入是空操作：不改指标、不改引用、不新建草稿、不新建线索。

跨租户行动者在选定和事件上都被拒绝，不改受害者租户的草稿，也不给任何租户加上发布权。

本包从不授予社交发布权。`revoke` 把该租户的发布许可锁成已撤销。`replay`、`edit`、`withdraw` 即使要求恢复，也不能打开这把锁，不能执行发布，也不能改写已存草稿。未知事件种类（包括名为 publish 的种类）拒绝且不改状态。

矩阵客户端返回错误，或客户端缺失时：不新增草稿；已有同一键草稿仍可读取；线索路径仍可用。本包造成的 `lead_writes`、`reply_bot_starts`、`charge_writes` 保持 0。`charged` 为 null。`billing_passed` 为 false。

日志和存储文档不得包含消息正文。通知形输出只有草稿 id、租户 id、资产 id、版本和回跳引用。

没有私信授权的渠道状态是 `unavailable`，不是 success。有授权也只是 `not_ingested`。`ClaimsEightPlatformDM` 恒为 false。
