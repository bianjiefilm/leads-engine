# HUI-1893 R3 销售工作台工程收口

日期：2026-09-29。总指挥已经拍板。本文件只扩展已合入的诚实切片 `e2d9683376dd57e1db5c8485cca96c7823b787dc`（PR #33），不回退它。

联合经营链 Touch → 真实 Notify → 同一条留资 → 首次跟进本轮不假装完成。没有真实 Notify 投递时，服务保持 NOT_VERIFIED。界面保留「联合经营链未完成」。这不阻止工作台工程。

## 不改什么

- 不引入 shadcn，不重做现有视觉和 EcoTopNav。
- 不重做租户映射。HUI-2316 已完成。
- 不改 touch-engine、public-ai。
- 不把草稿点击写成已提交的触达。`OutreachNotice` 不得发出「自动触达已成功」。
- 不把本仓夹具说成 Touch 已投递。
- 不占用 18101，也不把它当成获客桩。不绑定 18084、18120、8080、8081、5173。
- 真人采用保持 UNKNOWN。生产保持 NOT_VERIFIED。不写 Billing PASS。

## 本轮要锁住的行为

一条本租户线索（手工录入或本仓夹具，不是 Touch 投递）在销售工作台上同时给出：

- 来源
- 负责人；未分配时是「待分配」，不写成员 id，不写电话
- 状态
- 下一步

销售范围是 `own`，负责人范围是 `tenant`。两者不是同一个范围。销售看不见未分配给自己的行。

再次读取工作台，同一条线索仍在。另一租户的线索不可见。

`sync.crm=unknown` 不得画成「已跟进」。`statuses.followed` 只看已完结的跟进事实。

工作台响应带 `joint_chain`：`status=incomplete`，`label=联合经营链未完成`，`touch_delivered=false`。`outreach_submitted` 为 false。

## 测试

- Go 纯函数锁住经营链未完成、触达说明不含成功句、销售范围不等于负责人范围。
- HTTP 用本仓夹具式手工线索锁住来源、负责人或待分配、状态、下一步、刷新仍是同一条、跨租户不可见、未知同步不是已跟进。
- Vitest 用本仓夹具渲染上述四项，并锁住窄屏既有三条动作。
- 身份环境缺失时浏览器走查记 NOT_RUN。接口和组件测试不算浏览器通过。
